# 家庭环境监测系统测试方法

## 1. 测试目的

本测试用于验证家庭环境监测系统的设备采集、本地显示与蜂鸣、MQTTS 上报、华为云设备影子、Web 数据展示、阈值状态机、SQLite 持久化和 ntfy 手机通知。测试结果应区分以下层次：

- 代码测试通过；
- 固件或 Web 构建通过；
- 本机接口测试通过；
- 开发板真机测试通过；
- 设备、云、Web、手机端到端测试通过。

前一层通过不能代替后一层的验证。

## 2. 测试原则

1. 测试日志和截图不得包含 Wi-Fi 密码、DeviceSecret、MQTT 密码、IAM 密码或 Token；
2. 燃气测试不得使用真实泄漏或在密闭居住空间释放可燃气体；
3. MQ-2 未充分预热和标定前，只验证采集、显示和开关逻辑，不对读数作 ppm 结论；
4. 每个失败用例记录版本、环境、步骤、预期结果、实际结果、日志和复测结果；
5. 修改设备端阈值后需要重新生成配置、编译和烧录；Web 阈值只影响远程告警。

## 3. 测试环境

### 3.1 设备侧

- HiSpark Pegasus/Hi3861；
- AHT20、MQ-2、SSD1306 OLED、蜂鸣器；
- 2.4 GHz Wi-Fi；
- 固件烧录工具和串口终端；
- 可访问 NTP UDP 123、华为云 MQTTS TCP 8883 的网络。

### 3.2 服务侧

- Node.js 24 和 npm；
- 已配置的华为云 IoTDA 产品、设备和设备影子权限；
- 测试专用 SQLite 数据库；
- 测试专用 ntfy Topic；
- 至少一台浏览器和一部安装 ntfy 的手机。

测试时建议在 `.env` 中使用独立数据库：

```env
DB_PATH=data/environment-test.sqlite
```

不要让自动或破坏性测试操作正式家庭监测数据库。

## 4. 自动化测试

### 4.1 设备配置生成器测试

从仓库根目录运行：

```sh
cd src/applications/environment_monitor/device/tools
python3 -m unittest -v configure_device_test.py
```

当前包含 8 项测试，覆盖：

- C 字符串转义、生成文件权限和日志脱敏；
- Client ID 与 Device ID 匹配；
- Client ID 时间戳格式；
- 64 位十六进制派生 MQTT 密码；
- `ssl://host:8883` 安全接入地址；
- 上报周期与 CA PEM 格式；
- 本地报警阈值生成；
- 非法阈值与非法开关拒绝。

预期结果：显示 `Ran 8 tests` 和 `OK`。这些测试使用临时目录和占位凭据，不读取真实 `device.env`。

### 4.2 Web 后端单元测试

```sh
cd src/applications/environment_monitor/web
npm ci
npm test
```

当前包含 9 项测试，覆盖：

- 越界、持续异常、恢复缓冲、重复与乱序数据；
- 陈旧数据不报警和非法阈值原子回滚；
- 阈值、状态和通知重试的重启恢复；
- IoTDA 设备影子解析、服务时间和属性映射；
- ntfy UTF-8 JSON、令牌和失败响应；
- 阈值边界与未来时间拒绝；
- IAM Token 缓存和 IoTDA 401 后刷新；
- 缺失属性与非法上报时间拒绝；
- 恢复通知不能越过待重试的原告警。

预期结果：9 项测试全部通过，无失败和跳过。

### 4.3 类型检查与生产构建

```sh
cd src/applications/environment_monitor/web
npx tsc --noEmit
npm run build
```

预期结果：TypeScript 无错误，Web 生产构建成功并生成 `dist/client`。

### 4.4 固件构建测试

先使用有效私有配置生成 `environment_config.h`，再执行：

```sh
nix develop
cd src
hb build -f --gn-args='environment_cloud_enabled=true'
```

预期结果：编译和链接完成并生成可烧录固件，不出现头文件缺失、符号未定义或链接失败。该测试只证明构建链路可用，不能证明 MQTT 真机连接成功。

## 5. Web 接口测试

### 5.1 启动服务

```sh
cd src/applications/environment_monitor/web
npm run build
npm start
```

看到 `Environment API: http://127.0.0.1:8787` 后，在另一终端运行：

```sh
cd src/applications/environment_monitor/web
node backend/http-check.mjs
```

预期输出：

```text
HTTP checks passed: authentication, status, invalid edit rejection, static page.
```

该检查验证：无令牌请求返回 401、正确令牌返回 200 JSON、非法阈值返回 400 且原配置不变、静态首页可访问。

### 5.2 手工检查 API

将 `<ADMIN_TOKEN>` 替换为测试环境令牌：

```sh
curl -i http://127.0.0.1:8787/api/status
curl -i -H 'Authorization: Bearer <ADMIN_TOKEN>' \
  http://127.0.0.1:8787/api/status
```

预期结果：第一个请求返回 401 JSON；第二个请求返回 200，响应包含最新读数、历史、阈值、状态、告警和云连接状态。

## 6. 设备端功能测试

| 编号 | 测试内容 | 操作方法 | 预期结果 |
|---|---|---|---|
| DT-01 | 上电启动 | 烧录后重新上电并观察串口 | 系统初始化，无反复复位或崩溃 |
| DT-02 | AHT20 采集 | 在正常室内环境观察 OLED 和串口 | 温度、湿度周期更新且位于合理范围 |
| DT-03 | MQ-2 采集 | 充分预热后观察电阻值 | 数值可读取且无 NaN、无穷大等无效值 |
| DT-04 | OLED 显示 | 连续运行并观察页面刷新 | 三项数据及状态清晰，无明显残影或乱码 |
| DT-05 | 温湿度本地告警 | 使用安全受控方法使读数越过设备阈值 | OLED 显示异常，蜂鸣器发出单次长声 |
| DT-06 | 燃气报警保护 | 保持燃气报警关闭并改变传感器读数 | 未标定状态不因燃气电阻触发蜂鸣 |
| DT-07 | 燃气本地告警 | 标定完成后启用开关，并使用安全模拟或受控条件越界 | OLED 显示燃气异常，蜂鸣器连续三短声 |
| DT-08 | 断网本地能力 | 设备运行时关闭 Wi-Fi | 采集、OLED 和本地告警继续工作，网络任务自动重连 |

温湿度测试可采用手掌接近、改变通风或受控温湿度环境，避免加热元件直接接触传感器。燃气测试应优先使用标定装置或传感器输入模拟，不得制造真实家庭泄漏。

## 7. 云平台与端到端测试

| 编号 | 前置条件 | 操作步骤 | 预期结果 |
|---|---|---|---|
| IT-01 | 设备配置正确 | 设备上电并观察串口、IoTDA 控制台 | MQTT 连接成功，设备显示在线 |
| IT-02 | IT-01 通过 | 等待一个上报周期后查看设备影子 | `Environment` 服务三项属性和时间更新 |
| IT-03 | Web 后端运行 | 使用正确管理令牌打开页面 | 页面显示设备 ID、最新数据和云连接状态 |
| IT-04 | 连续上报 | 等待多个上报周期 | 历史趋势增加，重复或乱序数据不重复写入 |
| IT-05 | Web 和 ntfy 可用 | 将温度上限临时调到最新温度以下 | 产生一次 high 告警，手机收到一条通知 |
| IT-06 | IT-05 已报警 | 恢复阈值并使数据跨过恢复缓冲 | 产生 normal 恢复事件并收到恢复通知 |
| IT-07 | 多部手机订阅同一 Topic | 触发测试告警 | 本人和家人均收到相同事件编号的通知 |
| IT-08 | 保存了自定义阈值 | 重启 Web 后端 | 阈值、历史、告警状态和待发消息保留 |

Web 阈值测试不会触发设备蜂鸣器；验证本地蜂鸣器时必须修改设备端阈值并重新烧录，或使用受控环境使读数越过现有设备阈值。

## 8. 异常与恢复测试

### 8.1 Wi-Fi 断开与恢复

1. 设备正常在线并确认影子更新；
2. 关闭接入点或阻断设备网络；
3. 确认设备继续采集和本地报警；
4. 恢复网络；
5. 确认设备自动重连并继续上报最新数据。

预期结果：设备不阻塞采集任务，不补传大量过期数据，只上报恢复后的最近有效读数。

### 8.2 错误 MQTT 凭据

使用专门的测试固件配置错误派生密码并烧录，观察 MQTT 返回码。预期平台保持离线，串口可见鉴权失败；恢复正确 Client ID 和配套密码并重新烧录后上线。测试结束后销毁错误配置，不记录真实密码。

### 8.3 NTP 或 DNS 故障

临时使用不可达 NTP 地址或受控阻断 UDP 123。预期设备不绕过 TLS 时间和证书检查，并按策略重试；恢复网络后完成对时和 MQTT 连接。

### 8.4 数据陈旧

设备在线且页面已有读数后关闭设备，等待超过 `STALE_SECONDS`。预期页面保留最后读数并标记陈旧，不因陈旧读数产生新告警。

### 8.5 ntfy 失败与补发

1. 使用测试 Topic 触发一条告警；
2. 临时把 `NTFY_URL` 改为不可达地址并重启后端；
3. 确认页面显示通知失败或待发送；
4. 恢复正确地址并重启；
5. 确认原事件按顺序补发，再发送恢复事件。

网络超时可能出现 ntfy 已接收但本地未确认的情况，因此补发可能产生重复消息，应根据事件编号识别。

## 9. 家庭场景验收

在没有真实危险源的条件下组织一次家庭演练：

1. 由测试人员触发温湿度测试告警；
2. 记录 OLED 状态和蜂鸣器模式；
3. 记录本人及家人手机通知到达时间；
4. 家人按照约定流程电话确认居住者情况；
5. 恢复正常状态并确认收到恢复通知；
6. 模拟设备断网，确认本地提醒仍然有效；
7. 记录居住者能否区分长声和三短声，以及页面文字是否易懂。

建议验收指标：

- 居住者能够识别现场异常提示；
- 至少一名家人成功收到手机通知并完成确认；
- 持续异常不重复轰炸通知；
- 恢复消息不会早于原告警；
- 断网时本地监测与蜂鸣仍工作；
- 全过程不使用真实可燃气体泄漏。

## 11. 发布通过准则

系统作为家庭辅助监测工具投入连续运行前，应满足：

- 设备配置测试 8/8、Web 单元测试 9/9 全部通过；
- TypeScript 检查、Web 生产构建和启用云功能的固件构建成功；
- 设备采集、OLED、温湿度蜂鸣、IoTDA 上报和 Web 展示真机通过；
- ntfy 告警、恢复、失败重试和重启持久化通过；
- 数据陈旧、Wi-Fi 中断和设备重启均有明确状态与恢复行为；
- MQ-2 完成预热和受控标定后，才能启用燃气告警并验收；
- 家人确认通知渠道可用，居住者能够理解现场提示；
- 测试材料不包含任何真实凭据；
- 明确告知用户本系统不能替代合规的消防和燃气报警器。
