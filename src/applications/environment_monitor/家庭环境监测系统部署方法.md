# 家庭环境监测系统部署方法

## 1. 文档目的

本文说明家庭环境监测系统从华为云 IoTDA 配置、Hi3861 设备固件生成与烧录，到 Web 后端、SQLite 数据库和 ntfy 手机通知的完整部署流程。系统的数据链路如下：

```text
AHT20 / MQ-2
      ↓
Hi3861 + OLED + 蜂鸣器
      ↓ MQTTS（TCP 8883）
华为云 IoTDA 设备影子
      ↓ HTTPS
Node.js 后端 + SQLite
      ↓
Web 页面 / ntfy 手机通知
```

设备端本地显示和蜂鸣器不依赖 Web 服务；Web 阈值只控制远程告警和 ntfy 通知，不会自动下发到设备端。

## 2. 部署前准备

### 2.1 硬件与账号

- HiHope HiSpark Pegasus（Hi3861）开发板；
- AHT20 温湿度传感器、MQ-2 燃气传感器、SSD1306 OLED 和蜂鸣器；
- 可连接互联网的 2.4 GHz Wi-Fi；
- 华为云账号、IoTDA 实例、产品和设备；
- 可选的 ntfy 服务及手机 ntfy 客户端；
- 固件烧录工具和串口终端。

硬件连接：蜂鸣器使用 GPIO 9/PWM0，MQ-2 使用 GPIO 11/ADC5，AHT20 与 SSD1306 共用 GPIO 13、14/I2C0。

### 2.2 软件环境

- OpenHarmony/Hi3861 固件构建环境；
- Python 3；
- Node.js 24 及 npm；
- Git；
- 服务器部署时建议使用 Linux、systemd 和 Nginx/Caddy。

项目根目录记为：

```sh
cd /path/to/hi3861_hdu_iot_application
```

## 3. 配置华为云 IoTDA

### 3.1 创建产品模型

在目标 IoTDA 实例中创建使用 MQTT 协议、JSON 数据格式的产品，并添加服务 `Environment`。服务属性必须与设备端和 Web 后端保持一致：

| 属性名 | 类型 | 单位 | 建议范围 | 访问权限 |
|---|---|---|---|---|
| `temperature` | decimal | °C | -50～150 | 可读 |
| `humidity` | decimal | %RH | 0～100 | 可读 |
| `gas_resistance` | decimal | kΩ | 0～1000000 | 可读 |

如果平台中使用了其他服务 ID 或属性名，应同时修改设备端 `ENV_SERVICE_ID` 和 Web 端的 `IOTDA_*_PROPERTY` 映射。

### 3.2 注册设备

在产品下注册设备并妥善保存 Device ID 和 DeviceSecret。使用华为云 MQTT 连接参数生成工具，以当前 DeviceSecret 生成相互配套的 Client ID 和派生 MQTT Password。

注意：派生 MQTT Password 不是原始 DeviceSecret。若 Client ID 启用了时间校验，则 Client ID 时间戳和密码必须由同一次生成操作产生，过期后需要重新生成、编译和烧录。

### 3.3 准备应用侧访问权限

Web 后端需要查询设备影子，可选择以下一种鉴权方式：

1. 临时联调：填写短期项目级 Token `IOTDA_AUTH_TOKEN`；
2. 持续部署：填写 `IAM_DOMAIN`、`IAM_USERNAME` 和 `IAM_PASSWORD`，由后端自动获取和刷新 Token。

IAM 用户应具有查询目标设备影子的最小必要权限。`IOTDA_PROJECT_ID` 必须填写区域项目 ID，不能填写 IoTDA 实例 ID、资源空间 ID 或设备 ID。

## 4. 配置并构建设备端

### 4.1 创建私有设备配置

不要在仓库中保存真实 Wi-Fi 密码、DeviceSecret、MQTT 密码或证书私钥。将示例文件复制到 Git 仓库外的私有位置：

```sh
cp src/applications/environment_monitor/device/tools/device.env.example \
  /private/path/device.env
```

填写以下变量：

```sh
export ENV_WIFI_SSID='家庭WiFi名称'
export ENV_WIFI_PASSWORD='家庭WiFi密码'
export ENV_MQTT_URI='ssl://设备接入域名:8883'
export ENV_DEVICE_ID='华为云设备ID'
export ENV_MQTT_CLIENT_ID='生成工具给出的Client ID'
export ENV_MQTT_PASSWORD='生成工具给出的派生密码'
export ENV_MQTT_CA_FILE='/private/path/iotda-root-ca.pem'
export ENV_SERVICE_ID='Environment'
export ENV_REPORT_INTERVAL_SECONDS=30
export ENV_NTP_SERVER='time.pool.aliyun.com'
```

本地温湿度阈值可按家庭实际情况设置：

```sh
export ENV_LOCAL_TEMP_LOW=0
export ENV_LOCAL_TEMP_HIGH=35
export ENV_LOCAL_HUMIDITY_LOW=20
export ENV_LOCAL_HUMIDITY_HIGH=50
```

MQ-2 输出的是传感器电阻值而不是 ppm。完成充分预热和安全标定前，应保持：

```sh
export ENV_LOCAL_GAS_ALARM_ENABLED=0
```

标定完成后再填写 `ENV_LOCAL_GAS_LOW`、`ENV_LOCAL_GAS_HIGH` 并将开关设为 `1`。

### 4.2 获取 CA 证书

从华为云 IoTDA 官方设备接入文档下载与设备接入域名证书链匹配的根 CA PEM 文件。文件应包含：

```text
-----BEGIN CERTIFICATE-----
...
-----END CERTIFICATE-----
```

系统仅需要服务器根 CA 来校验华为云服务端证书，不需要设备客户端证书；设备身份由 Device ID、Client ID 和 MQTT Password 完成认证。

### 4.3 生成配置头文件

在当前终端加载私有配置并运行生成器：

```sh
set -a
. /private/path/device.env
set +a
python3 src/applications/environment_monitor/device/tools/configure_device.py
```

成功后生成：

```text
src/applications/environment_monitor/device/environment_config.h
```

该文件权限为 0600 且已被 Git 忽略。更换 Wi-Fi、设备凭据、CA 或本地报警阈值后，必须重新生成配置并重新编译烧录。

### 4.4 编译与烧录

在仓库的构建环境中执行：

```sh
nix develop
cd src
hb build -f --gn-args='environment_cloud_enabled=true'
```

正式应用已经由 `applications/sample/wifi-iot/app/BUILD.gn` 引用，无需再启用旧 demo。构建成功后，使用 HiBurn 等工具烧录生成的固件，并打开串口观察启动日志。

正常启动过程应依次出现：Wi-Fi 扫描完成、连接成功、NTP 对时成功、MQTT 连接成功和周期性数据上报。设备需要访问 NTP UDP 123 和 MQTTS TCP 8883。

## 5. 配置 Web 后端与 ntfy

进入 Web 应用目录并安装锁定版本的依赖：

```sh
cd src/applications/environment_monitor/web
npm ci
cp .env.example .env
```

如果 `.env` 已存在，应直接编辑，避免覆盖已有配置。先生成至少 16 位的管理令牌：

```sh
node -e "console.log(require('node:crypto').randomBytes(24).toString('hex'))"
```

`.env` 的核心配置示例：

```env
HOST=127.0.0.1
PORT=8787
ADMIN_TOKEN=替换为随机生成的管理令牌
API_PROXY_TARGET=http://127.0.0.1:8787
DB_PATH=data/environment.sqlite
STATIC_DIR=dist/client
POLL_SECONDS=10
STALE_SECONDS=90

IOTDA_ENDPOINT=https://应用侧接入域名
IOTDA_PROJECT_ID=区域项目ID
IOTDA_DEVICE_ID=设备ID
IOTDA_SERVICE_ID=Environment
IOTDA_TEMPERATURE_PROPERTY=temperature
IOTDA_HUMIDITY_PROPERTY=humidity
IOTDA_GAS_PROPERTY=gas_resistance

IOTDA_AUTH_TOKEN=
IAM_ENDPOINT=https://iam.cn-east-3.myhuaweicloud.com
IAM_DOMAIN=账号名
IAM_USERNAME=IAM用户名
IAM_PASSWORD=IAM用户密码

NTFY_URL=https://ntfy.sh
NTFY_TOPIC=自定义且不易猜测的主题名
NTFY_TOKEN=
```

`NTFY_URL` 填服务根地址，`NTFY_TOPIC` 单独填写主题。若使用受保护主题，再填写 `NTFY_TOKEN`。本人和家人的手机 ntfy 客户端订阅同一服务器和主题即可接收通知。

## 6. 运行 Web 应用

### 6.1 开发模式

开发模式需要两个终端。终端一启动 API：

```sh
cd src/applications/environment_monitor/web
npm run api
```

终端二启动前端：

```sh
cd src/applications/environment_monitor/web
npm run dev
```

浏览器访问前端输出的地址，通常为 `http://127.0.0.1:3000`。前端会把 `/api` 请求代理到 `API_PROXY_TARGET`。若只运行 `npm run dev`，会出现 `ECONNREFUSED 127.0.0.1:8787`。

### 6.2 本机生产模式

```sh
npm run build
npm start
```

浏览器访问 `http://127.0.0.1:8787`，输入 `.env` 中的 `ADMIN_TOKEN`。生产模式由同一进程提供静态页面与 API。

### 6.3 长期服务器部署

将 `web` 目录部署到服务器，执行 `npm ci && npm run build`，把 `.env` 权限设为仅服务账户可读，并持久化 `DB_PATH` 指向的 SQLite 文件。对外监听时设置 `HOST=0.0.0.0`，但不要直接将 8787 端口暴露到公网，应使用 Nginx/Caddy 提供 HTTPS 和访问控制。

systemd 服务示例：

```ini
[Unit]
Description=Home Environment Monitor
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=environment-monitor
WorkingDirectory=/opt/environment-monitor/web
ExecStart=/usr/bin/npm start
Restart=on-failure
RestartSec=5
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

部署后执行 `systemctl enable --now environment-monitor`，并定期备份 SQLite 数据文件。实际 Node/npm 路径应以服务器安装位置为准。

## 7. 部署验收

部署完成后按顺序确认：

1. 串口显示 Wi-Fi、NTP、MQTT 正常，IoTDA 控制台设备在线；
2. IoTDA 设备影子中 `Environment` 服务出现三项最新属性；
3. `npm start` 输出 `Environment API: http://...:8787`；
4. Web 页面能使用 `ADMIN_TOKEN` 登录并显示设备、云连接和通知状态；
5. 修改 Web 阈值后能保存，刷新页面配置仍存在；
6. 使用安全方式触发测试告警，本人和家人的手机收到 ntfy 消息；
7. 重启 Web 后端后，阈值、历史和待发送通知仍保留；
8. 断开网络时，设备端 OLED 与本地蜂鸣器仍能工作。

## 8. 常见故障

| 现象 | 原因与处理 |
|---|---|
| `ECONNREFUSED 127.0.0.1:8787` | 后端未启动或端口不一致；先运行 `npm run api`，检查 `PORT` 与 `API_PROXY_TARGET` |
| 网页提示访问令牌无效 | 页面输入的令牌与 `.env` 中 `ADMIN_TOKEN` 不一致；修改后重启后端 |
| 网页收到空响应或 JSON 解析失败 | 检查后端是否退出、代理目标是否正确，并直接访问 `/api/status` 查看 HTTP 状态 |
| 设备在线但 Web 无数据 | 核对项目 ID、设备 ID、服务 ID、属性名和 IAM 查询影子权限 |
| MQTT 返回码 4 | Client ID、派生密码或 Device ID 不匹配；重新成套生成凭据并烧录 |
| NTP 对时失败 | 检查 DNS、默认网关和 UDP 123；TLS 不应绕过时间与证书校验 |
| ntfy 无通知 | 核对 URL、Topic、Token和手机订阅；查看页面通知状态与待发送数量 |
| 燃气告警频繁误报 | 禁用燃气告警，充分预热并重新标定 MQ-2；不要把电阻值直接解释为 ppm |

## 9. 安全与运维要求

- 不提交 `.env`、`device.env`、`environment_config.h`、数据库和真实凭据；
- 为 IAM 用户配置最小权限，定期更换管理令牌和密码；
- 对外部署必须使用 HTTPS，并限制后端端口访问；
- 定期备份 SQLite 数据库并执行恢复演练；
- 定期检查设备离线、数据陈旧和通知失败状态；
- 本系统用于家庭环境风险的辅助发现，不能替代经过认证的燃气或消防报警器。
